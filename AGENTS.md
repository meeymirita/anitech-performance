## 3. Git: как и когда пушить (критично)

1. **Коммитить и пушить — только по просьбе пользователя.** Сообщения коммитов — **на английском**.
2. **Сначала пуш подмодуля(ей), потом родителя** — иначе checkout на GitHub падает (`not our ref`), сборки красные.
3. Порядок: коммит в подмодуле (`git add` конкретных файлов; `git status` до, `git show --stat` после — **коммит берёт ВЕСЬ индекс**, лишнее не добавлять) → push подмодуля (`git push origin HEAD:main`, многие подмодули стоят в detached HEAD — это нормально) → проверка, что ни один подмодуль не опережает origin:
   `git submodule foreach --quiet 'b=$(git rev-list --count @{u}..HEAD 2>/dev/null); [ "${b:-0}" != 0 ] && echo "$name ahead $b"; true'`
   → один коммит в родителе «Bump <лаба> submodule: …» → pull --rebase → push → **в конце `git status` чистый**.
4. **После каждого пуша:** `gh run list --limit 4` — зелёные оба: `Check site` и `Sync bucket`. Sync bucket молча падал уже дважды (06.10 — папка-заглушка без миниатюры; лечение: `gh run rerun` после пуша недостающего подмодуля). Без зелёного Sync bucket правки методичек на сайт не попадают.
5. Перед `cd <папка>` проверять `pwd` — оболочка может стоять внутри подмодуля.
6. Скрипт `tools/save-push.sh` (автоматизация вышеуказанного) содержит macOS-путь и `git add -A` — использовать осторожно, лучше вручную по шагам 3–4.

## 4. Методички: формат и как править

- Методички — HTML-«бандлы»: текст в сжатом JSON (`window.LAB` в base64+gzip внутри `<script type="__bundler/manifest">`). **Обычный grep/sed по HTML не работает и ЗАПРЕЩЁН** — одна невалидная правка делает страницу нечитаемой (поймано дважды).
- Инструмент — `fixes/common/_tools/bundle.py`:
  - CLI: `dump <html> [out]`, `grep <html> <regex>`, `sub <html> <старое> <новое> [--count N]`;
  - из Python (добавить путь `_tools` в sys.path): `load(path)`, `sub`, `rewrite(path, [(regex, repl), ...])`, `transform(path, fn)` — произвольная функция над текстом `window.LAB` (нужна для замены с экранированными `/` как `<\/`);
  - **`jsub(path, [(старое, новое, мин_вхождений), ...], unit='step-N-M')`** — замена по строкам внутри JSON без возни с экранированием; работает по строковым полям, включая html и плоский text;
  - `jre(path, [(regex, repl, мин), ...], unit=…)` — то же по регуляркам (нужно, когда в html выравнивание пробелами, а в плоском `text` оно схлопывается);
  - `patch_template(path, старое, новое)` — правка шаблона страницы (CSS/HTML в `<script type="__bundler/template">`).
- **Поле `text`** (плоский текст для поиска по сайту) обновляется jsub только при однострочной замене; видимый текст — поле `html`. После каждой правки проверять **видимый текст в браузере** (Chromium: открыть `<лаба>.html#step-N-M`, взять `body.innerText`, найти новую фразу), не только `check-site.py`.
- Нарезка для вычитки: `python3 fixes/common/_tools/prep.py <лаба> <папка>` (лабы в словаре `LABS`; есть go-start, go-pro). Даёт part_NN.txt (~20 тыс. символов) + pre_blocks.txt (все блоки кода).
- **Шаблон страницы одинаков у всех лаб** (CSS, консоль). Правка шаблона через `patch_template` → проблема есть у всех лаб, сказать владельцу. Известные правки шаблона: `pre{max-width:100%;overflow-x:auto}`, стили `.tip`/`.trap` (внесены в caddy.html и go-start.html 07.10; у остальных 20 лаб — не внесены, плашки «Ожидаемый результат» могут наезжать).
- После перевыгрузки методички из дизайн-исходников запускать `tools/patch-manuals.py` (кнопка «Все работы», защита от мигания поиска) и `tools/restore-symbols.py` (возвращает символы ✅❌☰ из диапазона U+2600–U+27BF, которые редизайн 02.10 стирал; ≈150 вставок).
- Блоки шагов («ПЕРЕД ШАГОМ», «Зачем», «Под капотом») генерируются скриптами `fixes/common/_tools/blocks/`; писать **новыми по смыслу**, прочитав сначала `why` шага (`dumpsteps`), иначе получится пересказ; ссылки проверять запросом до вставки.

После прогонов удалять только созданное (сравнивать списки образов/томов до/после). Тяжёлые прогоны (k6 stress/spike, сборка образов, сид 1 млн) — с предупреждением (греется). Docker Desktop на Mac — только с согласия владельца. В каждом k6-замере смотреть `http_req_failed`.
- **macOS:** нет `timeout` (замена: `gtimeout`/фон + kill); `sed -i ''`; zsh не разбивает переменную со словами (`$R` не работает — функцию); блокируется `rm` по маске; длинные python3 с кириллицей через stdin иногда не парсятся — писать в файл с `# -*- coding: utf-8 -*-`.
- **Контейнеры:** `docker --env-file` не обрезает комментарии в строке; `docker compose` создаёт каталог, если смонтированного файла нет; бесконечные команды (`\watch`, `ng serve`, `tail -f`) — только в фоне с ограничением; при монтировании файла несуществующий путь превращается в каталог.
- **Chromium/Playwright:** `npm i playwright` во временной папке; headless-снимки обязательно с `--host-resolver-rules="MAP cdnjs.cloudflare.com 0.0.0.0"` (иначе заставка вместо контента); модалка на главной открывается сама — перед скриншотом Escape; скриншоты в `screenshots-check/<дата>/`.
- **Сеть/DNS:** из песочницы порты 53 закрыты — проверять через DoH (`cloudflare-dns.com/dns-query`); к IP Cloudflare — `curl --resolve`. Локальный кеш DNS может показывать старое — не ошибка сайта.
- **Методички:** править только через `bundle.py` (раздел 4); после правки — видимый текст в браузере, не только check-site; `sync-bucket` падает, если у папки-лабы в репозитории есть методичка, но нет миниатюры/`image:` на карточке.
- **Changelog:** блок дня вставлять в КОНЕЦ массива `DAYS` (перед `];` и `// ── рендер`) — блок внутри `stats` даёт пустую плитку; `node -e` синтаксис такое не ловит.
- **Картинки:** в README лаб — только raw.githubusercontent (camo не берёт бакет Yandex); корневой README — `docs/screenshots/*.jpg`; обложки сайта — только бакет, локальных путей `<лаба>/<файл>.png` в site-коде нет.
- **Секреты:** никогда не писать в файлы и не просить в чат. Публичные репозитории: секретов в истории нет (аудит 05.10) — не добавлять. `rabbitmq/laravel-app` — реальный проект владельца (vendor не под git).
- **Сухие прогоны:** стенды собираются во временной папке ВНЕ репозитория; блоки кода из методичек теряли символы эмодзи и резались по заголовкам — сверять с HTML; «собрано по блокам» ≠ «скопировано дословно»; полный список допущений — `_dryrun-assumptions.md`.
- В `works/changelog.html` первый `<script>` — основной (в начале редирект http→https); синтаксис проверять перед коммитом.

## 11. Как вести владельца по лабе (когда она проходит)

Сначала она пробует сама, потом разбираем («напиши как понял — поправлю»). Не вываливать теорию заранее. Поведение показывать запуском кода в контейнере лабы, а не словами. На «сложно/непонятно» — упростить (аналогия, короткая карта файла), попросить показать, что именно непонятно. Любое утверждение о коде проверять запуском, прежде чем выдавать как факт.
