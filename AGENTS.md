# AGENTS.md — правила для агентов (Kimi Code, Claude и др.)

Этот файл агенты читают автоматически. **Единый источник правил проекта — `CLAUDE.md` в корне: прочти его целиком перед работой.** Здесь — краткая выжимка критичного, чтобы не пропустить главное.

## Проект

Личная учебная программа владельца (Laravel/PHP-разработчик). Общение — **на русском**. Родительский репозиторий `meeymirita/anitech-performance` + каждая папка-лаба — отдельный git-подмодуль со своим репозиторием `meeymirita/<тема>-lab`. Сайт: собственный сервер с Caddy, деплой таймером из GitHub; картинки/методички — бакет Yandex (синхронизация Actions `sync-bucket.yml` после пуша).

## Критичные правила

1. **Методички — HTML-«бандлы»** (текст в сжатом JSON `window.LAB`). Править ТОЛЬКО через `fixes/common/_tools/bundle.py` (`jsub`/`jre`/`transform`/`patch_template`); grep/sed по HTML запрещены. После правки — `python3 tools/check-site.py` и проверка видимого текста в браузере (`jsub` может заменить только в скрытом поле `text`).
2. **Git: сначала пуш подмодуля, потом родителя** (иначе checkout на GitHub падает). Сообщения коммитов — на английском. Коммитить/пушить — только по просьбе пользователя. `git add` конкретных файлов; перед коммитом `git status`, после — `git show --stat` (коммит берёт весь индекс). Перед пушем родителя — проверить, что ни один подмодуль не опережает origin. После пуша — `gh run list --limit 4`: зелёные `Check site` и `Sync bucket`.
3. **После любой правки** (без напоминаний): пересобрать зависимое (`tools/build-verification.py`, `build-progress.py` → затем `build-seo.py`, `check-site.py`), обновить записи — `works/changelog.html`, `fixes/common/_state-log.md` (новые сверху), находки — `fixes/<направление>/<лаба>.md`, статусы — `fixes/common/_verification.md` (единственный источник для verification.html/status.js).
4. **Ключи/пароли никогда не писать в файлы и не просить в чат.**
5. **Актуальные статусы — в файлах, не в памяти:** корневой `README.md` + README лаб («Статус:»), `fixes/common/_proofread.md` (вычитка), `_verification.md` (чем проверено), `_state-log.md` (журнал), `_order.md` (порядок лаб), `site.md` (версии-стандарт: PHP 8.4, Node 24, Redis 8, PostgreSQL 18, Go 1.27, kind v0.33/K8s 1.37 и т.д.).
6. Docker — общая машина с чужими контейнерами: трогать только свои (`--filter name=…`), после прогонов удалять только созданное. Тяжёлые прогоны (k6, сборка образов, сиды) — с предупреждением пользователю.

## Уроки (не повторять ошибок)

- Ломать методички нельзя: невалидный JSON после правки = нечитаемая страница. Всегда `jsub` + `check-site.py`.
- `pwd` перед `cd` (оболочка может быть внутри подмодуля).
- На macOS нет `timeout`; `sed -i ''`; zsh не разбивает переменные со словами.
- В `works/changelog.html` правки — в первом `<script>`, синтаксис проверять перед коммитом.
- `screenshots-check/` — локальная папка, в git не идёт.
