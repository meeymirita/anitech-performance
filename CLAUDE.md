**Формат методичек (с 02.10.2026):** HTML-«бандл» — текст лежит в сжатом JSON внутри файла (`window.LAB`), обычный grep/sed по нему не работает. Читать и править через `fixes/common/_tools/bundle.py` (`dump` / `grep` / `sub`, из Python — `rewrite`); `prep.py` умеет оба формата.

**Ещё про методички:** `bundle.jsub(path, [(старое, новое, мин_вхождений)], unit='step-N-M')` — замена по строкам внутри JSON (html и плоский `text`), `jre` — то же регулярками, `patch_template` — правка шаблона. Шаблон одинаков у всех лаб: стили `.tip`/`.trap` и `pre{max-width:100%;overflow-x:auto}` внесены только в `caddy.html` и `go-start.html` (07.10), у остальных 20 лаб нет — плашки «Ожидаемый результат» могут наезжать. После перевыгрузки методички из дизайн-исходников — `tools/patch-manuals.py` и `tools/restore-symbols.py` (возвращает символы ✅❌☰, которые редизайн 02.10 стирал). Скриншоты headless Chromium — с `--host-resolver-rules="MAP cdnjs.cloudflare.com 0.0.0.0"`, иначе вместо контента заставка.

**Если методичка пришла самодельным HTML (не бандлом)** — так было с Caddy Lab 05.10: шаблон (`<script type="__bundler/manifest">` + `<script type="__bundler/template">`) у всех лаб побайтово одинаков, отличаются только случайные UUID ассетов в манифесте. Если данные в `window.LAB` уже той же формы (`units[]` с `kind: theory/step/ref`, `sessions[].steps[]` — ссылки по ключу, поля `why`/`deep`/`quiz`) — переупаковка тривиальна: взять `.html` любой существующей лабы как есть и `bundle.transform(path, lambda old: новый_текст_window_LAB)` подменяет payload, валидирует JSON сам. ## Правила git

1. **Сначала пушить подмодуль, потом родителя.** Если родитель ссылается на коммит подмодуля, которого нет на GitHub, сборка Pages падает на checkout (`not our ref …`). Так было 26.09 с `works`.
2. Перед пушем родителя проверить, что ни один подмодуль не опережает свой origin:
   `git submodule foreach --quiet 'b=$(git rev-list --count @{u}..HEAD 2>/dev/null); [ "${b:-0}" != 0 ] && echo "$name ahead $b"; true'`
3. Порядок коммитов: коммит в подмодуле → отдельный коммит в родителе «Bump <лаба> submodule: …».
4. Коммитить и пушить только по просьбе пользователя. Сообщения коммитов — на английском.
5. Оболочка может стоять внутри подмодуля. Проверять `pwd` перед `cd <папка>`.
6. `git commit` берёт ВЕСЬ индекс, а не только последний `git add`: перед коммитом смотреть `git status`, после — `git show --stat`, чтобы в коммит не попало лишнее (06.10 так в коммит методички попал чужой файл — пришлось пересобирать до пуша). Личные файлы владельца `caddy/docs/*.md` в git не добавлять (они в `.git/modules/caddy/info/exclude`).

## Уроки для себя (не повторять)

- Не запускать фоновые циклы, перезапускающие контейнеры; не `docker kill` всех — только `--filter name=…`; перед тяжёлыми прогонами (k6 stress/spike, сборка образов, сид 1 млн) предупреждать — ноутбук пользователя греется; в каждом k6-замере проверять `http_req_failed`.
- Shell: проверять `pwd` перед `cd <папка>` (оболочка может оказаться внутри подмодуля); в zsh переменная со словами не разбивается (`$R` не работает — писать функцию); на macOS нет `timeout`; `sed -i ''`; встроенная проверка блокирует `rm` по маске (`rm -f dir/*`) — не обходить; длинные Python-скрипты с кириллицей через stdin иногда не парсятся — писать в файл с `# -*- coding: utf-8 -*-`.
- `docker --env-file` не обрезает комментарии в строке (`JWT_EXPIRES_IN=3600  # секунды` → невалидное значение); `docker compose` создаёт каталог, если смонтированного файла нет (`init.sql` → «Is a directory»); бесконечные команды (`\watch`, `ng serve`, `tail -f`) — только в фоне и с ограничением.
- Playwright: `npm i playwright` во временной папке (старый `node_modules` может быть пустым), Chromium — `~/Library/Caches/ms-playwright`; модальное окно на главной открывается само — перед скриншотом карточки нажимать Escape; скриншоты класть в `screenshots-check/<дата>/` (в git не идут, не удалять).
- **После любой правки методички проверять ВИДИМЫЙ текст в Chromium** (открыть `<лаба>.html#step-N-M`, взять `body.innerText`, найти новую фразу), а не только `check-site.py` и `bundle.load` — `jsub` может заменить только в скрытом `text`. Скрипт аудита писался разово в scratchpad (`audit.js`: список [шаг, фраза] по лабам).
- DNS из песочницы: порты 53 закрыты (`dig` не работает) — проверять через DoH (`curl -H 'accept: application/dns-json' https://cloudflare-dns.com/dns-query?name=…&type=…`); к IP Cloudflare — `curl --resolve host:443:188.114.97.0`. Локальный кеш DNS показывает старое — это не ошибка сайта.
- Блоки шагов в методичках (`fixes/common/_tools/blocks/`) писать **новыми по смыслу**, а не пересказом «Зачем»: сначала прочитать `why` шага (`dumpsteps`), иначе повтор; ссылки проверять запросом до вставки (скрипт это делает).
- В `works/changelog.html` первый `<script>` — теперь основной (редирект http→https лежит внутри него в начале); проверка синтаксиса из раздела «Проверка перед коммитом» остаётся рабочей.
- **Docker Desktop на этом Mac запускать только с согласия пользователя** (диск был заполнен на 96%, память на 75%): первый старт мог не подниматься ~10 минут (лечит `docker desktop restart`); после проверки удалять только созданное (сравнивать списки образов/томов «до» и «после»), приложение закрывать. Не использовать `rm -rf *` после `cd` — встроенная проверка блокирует. При монтировании файла в Docker несуществующий путь превращается в каталог.
- Ломать методички нельзя: правка, давшая невалидный JSON, делает страницу нечитаемой (поймано дважды: Vue и Laravel). Всегда `jsub`, потом `check-site.py`.

ООП-лабу целиком в Laravel и Docker ещё не собирали — вычитка проверяла только доменный код.

## Как вести пользователя по лабе

- Сначала пользователь пробует сам, потом разбираем («напиши как понял — поправлю»). Не вываливать длинную теорию заранее.
- Показывать поведение, запуская код в контейнере лабы (`var_dump`, специально сломанные примеры), а не только объяснять словами.
- На «сложно / непонятно» — не добавлять деталей, а упростить: аналогия, короткая карта файла, попросить показать, что именно непонятно.
- Любое утверждение о коде проверять запуском, прежде чем выдавать как факт.
- Ответы короткие и конкретные. Не пересказывать уже пройденное.
