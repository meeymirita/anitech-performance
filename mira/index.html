Как устроен ANITECH и что делать, чтобы он работал

Эта страница — ваша инструкция. Если что-то забыли или сломалось, начните отсюда: здесь написано, что где лежит, что делать пошагово и какие команды вставлять.

Простыми словами

У сайта три «места жизни»: GitHub (там хранятся все файлы и история), сервер (там сайт видят люди) и бакет Yandex (там лежат тяжёлые файлы: методички и картинки). Вы меняете файлы у себя, отправляете их на GitHub командой «пуш», а дальше всё само разъезжается по серверу и бакету. Руками ничего никуда загружать не надо.

Главное правило безопасности

Пароли и ключи нигде не пишем: ни в чат, ни в письма, ни в этот сайт. Здесь только названия ключей и места, где они лежат. Если ключ всё-таки попал в чат или на скриншот, считайте его скомпрометированным и перевыпустите (рецепт ниже).

Страница закрыта паролем на уровне сервера (логин mira) и от поисковиков. Но исходный файл лежит в публичном репозитории на GitHub, поэтому ничего секретного здесь быть не должно: только названия и ссылки на ваши панели (в них всё равно нужен ваш логин).

Из каких частей это состоит — одним абзацем на каждую

  • GitHub — «облачная папка» с историей: можно вернуться к любой версии файла. Основной репозиторий anitech-performance содержит сайт, а каждая лаба лежит в своём отдельном репозитории, подключённом внутрь (это называется «подмодуль»).
  • Сервер — компьютер в интернете (Ubuntu), на нём программа Caddy отдаёт сайт по адресу anitech.meeymirita.ru. Туда сайт попадает сам, по таймеру.
  • Бакет — «облачный склад» Yandex. Методички, обложки и фото открываются прямо оттуда, чтобы не нагружать сервер.
  • Воркер Cloudflare — маленькая программа, которая хранит ваш прогресс по лабам, чтобы он не пропадал, если вы очистите браузер или откроете сайт на другом устройстве.
  • Cloudflare также отвечает за DNS: это «телефонная книга», которая говорит браузеру, что anitech.meeymirita.ru находится на сервере 45.10.166.23.
Что важно понять

Источник правды — GitHub. Сервер и бакет — «копии для показа». Если на сайте что-то не так, правим в репозитории и пушим, а не лезем править сервер руками (иначе при следующем обновлении правка исчезнет).

02

Что случается после «пуш»

По секундам: вы отправили изменения — что происходит дальше.

  1. Вы (или я по вашей просьбе) запускаете пуш Команда bash tools/save-push.sh "что изменили" сохраняет изменения и отправляет их на GitHub. Сначала отправляются подмодули (отдельные репозитории лаб), потом главный репозиторий. Порядок важен: иначе главный будет ссылаться на то, чего ещё нет на GitHub.
  2. Через секунды просыпается робот GitHub Actions Он называется «Sync bucket». Скачивает репозиторий, сравнивает файлы с бакетом и загружает в бакет только новое и изменённое. Старые версии заменяемых файлов он сначала откладывает про запас (см. раздел «Бакет»). Занимает около 30–40 секунд.
  3. Через ≤ 1 минуты срабатывает таймер на сервере Раз в минуту сервер спрашивает GitHub «есть новое?». Если да, скачивает и копирует в папку сайта только то, что нужно сайту. Если нет, ничего не делает.
  4. Сайт обновлён Откройте anitech.meeymirita.ru и нажмите Cmd+Shift+R (обновить без кеша). На практике изменение появляется через 20–60 секунд.

Проверить, что робот отработал: вкладка Actions в репозитории — зелёная галочка у последнего запуска.

Ключи и пароли: названия и места

Значений здесь нет и не должно быть. Только как называется, где лежит, зачем и как заменить.

YC_ACCESS_KEY_ID
Где лежит
GitHub → репозиторий → Settings → Secrets and variables → Actions. Копия может быть на Mac в ~/.config/anitech/yc.env, если вы захотите запускать загрузку у себя.
Зачем
«Логин» робота, чтобы он мог загружать файлы в бакет Yandex. Относится к сервисному аккаунту anitech-object-storage.
Как заменить
См. рецепт «Заменить ключи Yandex» ниже.
YC_SECRET_ACCESS_KEY
Где лежит
Там же, рядом с предыдущим.
Зачем
«Пароль» робота к бакету. Показывается один раз при создании ключа в Yandex, потом его не посмотреть — только создать новый.
Как заменить
Вместе с логином, одним рецептом.
PASSWORD
Где лежит
Cloudflare → Workers → anitech-progress → Settings → Variables and Secrets (тип Secret). И в вашей голове.
Зачем
Пароль, который вы вводите в методичке (кнопка ☁), чтобы получить доступ к своему прогрессу. После 10 неверных попыток с одного адреса воркер блокирует вход на 15 минут.
Как заменить
В панели воркера изменить значение секрета и нажать Deploy. Потом заново ввести пароль на устройствах.
EXTRA_ORIGINS
Где лежит
Cloudflare → воркер → Settings → Variables (тип Text, это не секрет).
Зачем
Список адресов, которым можно обращаться к воркеру. Сейчас там адрес бакета, потому что методички открываются оттуда. Если появится новый адрес сайта и в методичке напишет «нет связи с Worker», его надо добавить сюда.
Пароль страницы /mira/
Где лежит
На сервере в файле /etc/caddy/mira-auth.conf лежит не сам пароль, а его «отпечаток» (хеш). Логин: mira. Сам пароль знаете только вы.

Чтобы страницу не открыл посторонний, даже если узнает адрес.

05

Сервер

Что на нём стоит и как зайти.

Что на сервере

  • Система: Ubuntu 22.04, адрес 45.10.166.23.
  • Caddy (веб-сервер). Конфиг — /etc/caddy/Caddyfile. В нём два сайта:
    • anitech.meeymirita.ru — отдаёт папку /var/www/anitech-performance;
    • meeymirita.ru — передаёт запросы на 127.0.0.1:8080, то есть вашему другому сайту (он работает в Docker).
    Сертификаты для https Caddy выпускает и продлевает сам. С http на https перенаправляет тоже сам.
  • Docker-контейнеры (meeymirita-frontend, -backend, -postgres, -redis и amnezia-awg2, похоже на VPN). Их не трогаем: это другой проект. У всех включён автозапуск после перезагрузки.
  • Таймер деплоя anitech-deploy.timer — раз в минуту обновляет сайт. Рабочая копия репозитория — /opt/anitech-src.

Как зайти на сервер

на вашем Mac
ssh -i ~/.ssh/id_anitech root@45.10.166.23

Спросит пароль от ключа (тот, что вы придумали при создании), а не пароль сервера. В начале строки появится root@weaselcloud…. Выйти: exit.

Важно не перепутать

Команды из этой страницы делятся на два вида: «на вашем Mac» (в строке …@MacBook) и «на сервере» (в строке root@weaselcloud). Над каждым блоком с командой написано, где её выполнять. Вставили не туда — не страшно, но ничего не сработает или создастся не там (как было с ключом).

Как устроен деплой сайта

Скрипт /opt/anitech-src/deploy/deploy-site.sh делает три вещи: подтягивает свежий main с GitHub, сравнивает номер версии с уже выложенным (он записан в /var/lib/anitech-deploy.rev) и, если версия новая, копирует нужное сайту в папку Caddy. Копируется только: index.html, favicon.svg, images/, mira/, works/ (без тяжёлых картинок). Всё остальное (папки лаб, методички) сайту не нужно: методички открываются из бакета.

на сервере
# когда срабатывал таймер и что выложил
systemctl list-timers anitech-deploy.timer
journalctl -u anitech-deploy.service -n 20 --no-pager

# выложить прямо сейчас, не ждать минуту
FORCE=1 /opt/anitech-src/deploy/deploy-site.sh

Чего на сервере ещё не сделано

  • 25 обновлений пакетов не установлены и сервер просит перезагрузку (System restart required). Вы решили отложить. Когда захотите: apt-get update && apt-get upgrade -y, затем reboot. Контейнеры и Caddy поднимутся сами.

Бакет с файлами (Yandex Object Storage)

Там лежат методички, обложки, миниатюры и фото. Адрес файлов: https://meeymirita-files.storage.yandexcloud.net/…

как устроены папки
<лаба>/<лаба>.html       методичка
<лаба>/README.md           README лабы
<лаба>/thumb.webp          миниатюра для карточек
<лаба>/<имя>.png           обложка
site/me.jpg                 фото автора
site/screenshots/*.jpg      скриншоты окна «О проекте»
old_files/last-sync/        прежние версии файлов с последней загрузки
old_files/…остальное        ваши старые выгрузки (робот не трогает)

Как файлы попадают в бакет

Вручную ничего загружать не нужно. Робот GitHub Actions после каждого пуша запускает скрипт tools/sync-bucket.py. Он сверяет файлы репозитория с бакетом (по контрольной сумме) и:

  • загружает новые файлы;
  • заменяет изменённые;
  • удаляет то, чего в репозитории уже нет (в папках лаб и site/).
Страховка

Перед тем как заменить или удалить файл, робот копирует его прежнюю версию в old_files/last-sync/. Предыдущая копия там стирается, то есть хранится ровно один шаг назад. Если пуш что-то сломал, прежнюю версию можно взять оттуда (рецепт «Вернуть старую версию файла»).

Посмотреть, что изменится, ничего не меняя

на вашем Mac, из папки проекта
python3 tools/sync-bucket.py --dry-run

Ключи для этого не нужны. «Загрузить 0, удалить 0» означает, что бакет полностью совпадает с репозиторием.

07

Прогресс прохождения

Как сохраняются ваши галочки в методичках.

  • Сначала в браузере. Каждая отметка шага хранится в памяти браузера (localStorage) отдельно для каждой лабы. Если ничего больше не делать, прогресс живёт только на этом устройстве и в этом браузере.
  • Потом в облаке. Если вы нажали ☁ (слева внизу в методичке или на странице «Все работы и прогресс») и ввели пароль, копия прогресса уходит в воркер Cloudflare и лежит в KV. С другого устройства войдите тем же паролем — прогресс подтянется.
  • Если с двух мест разное: побеждает более новое; пустое никогда не затирает непустое.
  • Запасной путь: в той же панели есть «выгрузить файл» и «загрузить файл».
Проверено 05.10.2026

Вы отметили шаги, вышли, очистили хранилище браузера, снова ввели пароль, и прогресс вернулся. Значит облако работает.

Код воркера: tools/progress-worker/worker.js. Клиент: works/js/sync.js. Воркер отвечает только тем адресам, которые в списке: https://anitech.meeymirita.ru и адрес бакета (последний — через переменную EXTRA_ORIGINS и в коде).

Осторожно

Если менять worker.js в репозитории, то код в панели Cloudflare сам не обновится: его надо вставить туда вручную и нажать Deploy.

на сервере

Логин всегда mira. Выбирайте пароль, который нельзя угадать по названию сайта.

Потерял SSH-ключ или забыл пароль от него

На сервер больше не зайти по паролю, поэтому используйте консоль в личном кабинете хостинга (она работает независимо от SSH). Порядок:

  1. Создайте новый ключ на Mac: ssh-keygen -t ed25519 -f ~/.ssh/id_anitech2.
  2. Покажите публичную половину на Mac: cat ~/.ssh/id_anitech2.pub и скопируйте строку целиком.
  3. В консоли хостинга выполните echo 'СТРОКА' >> /root/.ssh/authorized_keys (вместо СТРОКА вставьте скопированное).
  4. Проверьте вход: ssh -i ~/.ssh/id_anitech2 root@45.10.166.23. Старую строку из authorized_keys потом уберите.

Если что-то сломалось

Симптом → причина → что делать.

Робот (Actions) упал с ошибкой «not our ref»

Причина: главный репозиторий ссылается на версию подмодуля, которой ещё нет на GitHub (значит, подмодуль не отправлен).

Что делать: отправить подмодуль (git push origin HEAD:main внутри его папки), потом перезапустить: gh run rerun <номер>. Либо просто попросите меня.

Картинка или методичка не открывается

Причина: файла нет в бакете (робот не отработал или имя не совпало).

Что делать: посмотреть вкладку Actions; выполнить python3 tools/sync-bucket.py --dry-run: он покажет, чего не хватает.

На сайте старая версия

Причина: кеш браузера или таймер на сервере не сработал.

Что делать: Cmd+Shift+R; затем рецепт «Сайт не обновился».

В окне «Оглавление» написано «не удалось загрузить»

Причина: нет файла works/js/toc.json на сервере или он устарел.

Что делать: python3 tools/build-toc.py, потом пуш.

В методичке «нет связи с Worker»

Причина: адрес, с которого открыта методичка, не разрешён воркеру (так было 05.10 с бакетом).

Что делать: добавить адрес в переменную EXTRA_ORIGINS в панели воркера (через запятую) и нажать Deploy.

Методичка не открывается после правки

Причина: в данных внутри неё оказался некорректный JSON.

Что делать: правки методичек делать только через скрипты bundle.py, потом check-site.py. Если уже сломали, скажите мне: вернём прошлую версию из истории GitHub.

Не пускает на сервер

Причина: команда выполняется не на Mac, нет файла ключа или неверный пароль от ключа.

Что делать: см. рецепты «Зайти на сервер» и «Потерял SSH-ключ».

Правила, чтобы ничего не сломать

  • Пушить только через tools/save-push.sh (или просить меня): он соблюдает порядок «сначала подмодули, потом главный».
  • Не править файлы руками на сервере и в бакете: при следующем пуше их вернут к состоянию репозитория. Правим всегда в репозитории.
  • Ключи и пароли не отправлять в чат, почту, скриншоты. Если отправили, перевыпустить.
  • Не трогать на сервере Docker-контейнеры и блок meeymirita.ru в Caddyfile: это другой проект.
  • Правки методичек только через скрипты (bundle.py), не обычным редактором.
  • Перед пушем: python3 tools/check-site.py должен показать «OK».
  • Исходный код этой страницы публичный (репозиторий открытый): пароль на ней защищает только саму страницу на сервере, поэтому секреты сюда не писать никогда.
  • GitHub Pages выключен, сайт живёт только на сервере. Заново его не включать.

Словарик

Репозиторий
Папка проекта с историей изменений. Хранится на GitHub.
Коммит
Один сохранённый «снимок» изменений с подписью, что изменили.
Пуш (push)
Отправить свои коммиты на GitHub.
Подмодуль
Отдельный репозиторий, подключённый внутрь главного. Каждая лаба — подмодуль. Поэтому пуш делается в два этапа: сначала лабы, потом главный.
GitHub Actions
Роботы GitHub, которые запускаются сами после пуша. У нас один: «Sync bucket».
Секрет GitHub
Пароль, спрятанный в настройках репозитория: робот его использует, а в логах и коде он не виден.
Бакет (Object Storage)
Облачное хранилище файлов у Yandex. Каждый файл имеет адрес.
Статический ключ доступа
Пара «логин + пароль» для программ (не для людей), чтобы они могли работать с бакетом.
Caddy
Программа-веб-сервер. Принимает запросы из интернета и отдаёт страницы; сама получает сертификаты для https.
Caddyfile
Файл настроек Caddy.
SSH
Защищённый способ зайти в командную строку удалённого сервера.
SSH-ключ
Пара файлов: секретный (остаётся у вас) и публичный («замок» на сервере). Надёжнее пароля.
Таймер systemd
«Будильник» на сервере, который по расписанию запускает скрипт. У нас — раз в минуту обновляет сайт.
DNS
«Телефонная книга» интернета: переводит имя сайта в адрес сервера. У нас ею управляет Cloudflare.
Cloudflare Worker
Маленькая программа в облаке Cloudflare. У нас хранит прогресс.
KV
Простое хранилище «ключ → значение» у Cloudflare. Там лежит прогресс.
CORS
Правило браузера: страница с одного адреса может обращаться к другому адресу, только если тот это разрешил. Из-за него воркеру нужен список разрешённых адресов.
localStorage
Память браузера для сайта. Очищается, когда вы чистите данные сайта.
