Как устроен ANITECH PERFORMANCE и где что лежит

Инструкция владельца: из каких частей собран сайт, в каких сервисах что хранится, какие ключи где висят и что делать, если что-то сломалось. Значений ключей здесь нет и быть не должно — только их имена и места.

Как всё связано

Правка на ноутбуке→ GitHub: подмодуль, потом родитель→ GitHub Actions «Sync bucket»→ Бакет Yandex Object Storage
Браузер→ Cloudflare (DNS, HTTPS)→ Сервер с Caddy→ страницы сайта+ картинки и методички из бакета
Методичка / страница прогресса⇄ Cloudflare Worker + KV(синхронизация прогресса)
Репозиторий — источник правды. Бакет только раздаёт файлы и всегда приводится к репозиторию (лишнее удаляется). Прогресс прохождения живёт отдельно: в браузере и в Cloudflare KV.

Что умеет сайт

Главная (index.html)

  • Карточки всех лаб с категориями, группами, сноской «что требуется» (Docker, аккаунт, домен, ключи) и обложкой из бакета.
  • Карта маршрутов и треки («Весь путь» и тематические): порядок и зависимости лаб.
  • Первый экран с настройками (шестерёнка), окно «О проекте» со скриншотами и фото автора.

Страница лабы (works/<лаба>.html)

  • Табы «Чему вы научитесь», стек, сессии, схема архитектуры (можно двигать), FAQ.
  • Окно «Оглавление» — читает готовый works/js/toc.json, не зависит от сети до бакета.
  • Ссылка на методичку открывает файл из бакета.

Методичка (<лаба>/<лаба>.html, лежит в бакете)

  • Один HTML-файл-«бандл»: текст внутри сжатого JSON. Правится только через fixes/common/_tools/bundle.py.
  • Режимы «Лента» и «По шагам», таймеры по сессиям, отметки «Проверь себя», поиск по лабе (Ctrl K), тёмная тема.
  • У каждого шага: «Зачем», «Под капотом», «Почитать», ожидаемый результат, блоки «сломать → починить».
  • Кнопка «Все работы», окно «Что нужно знать до старта», кнопка ☁ синхронизации прогресса.

Служебные страницы

  • works/progress.html — все работы и общий прогресс.
  • works/changelog.html — хронология (колонки «Главное», «Вычитка и запуск», «Полный отчёт»).
  • works/verification.html — что и чем проверено.
  • /mira/ — эта страница.

Прогресс прохождения

  • Отметки шагов и разделов хранятся в localStorage браузера (ключи вида lab-redesign-v1:<лаба>).
  • Если вы вошли по паролю (кнопка ☁ слева внизу в методичке и на странице прогресса), копия уходит на Cloudflare Worker anitech-progress и хранится в KV. С другого устройства войдите тем же паролем — прогресс подтянется.
  • Слияние: побеждает более новое; пустое не затирает непустое.
  • Запасной путь — экспорт/импорт файлом в той же панели.
  • Код воркера: tools/progress-worker/ (worker.js, README, test.mjs), клиент — works/js/sync.js. Воркер разрешает запросы только с известных адресов (список в worker.js).
Если менять worker.js в репозитории — править и копию в панели Cloudflare вручную, она не обновляется сама.

Бакет Yandex Object Storage

Имя meeymirita-files, публичное чтение, адрес https://meeymirita-files.storage.yandexcloud.net/….

<лаба>/<лаба>.html        методичка
<лаба>/README.md            README лабы
<лаба>/thumb.webp           миниатюра для карточек
<лаба>/<имя>.png            обложка (имя берётся из ссылки image: в index.html)
site/me.jpg                 фото автора
site/screenshots/*.jpg      скрины окна «О проекте»
old_files/                  ваши старые выгрузки (скрипт не трогает)
old_files/last-sync/        прежние версии файлов с последней загрузки (скрипт перезаписывает)

Источники в репозитории: методичка и README — в подмодуле лабы; миниатюры — works/images/thumbs/<лаба>.webp; обложки — works/images/<лаба>.png; фото — works/images/me.jpg; скрины — docs/screenshots/.

  • Руками в консоли Yandex ничего загружать не нужно — скрипт tools/sync-bucket.py сам загружает новое, заменяет изменённое (по MD5) и удаляет лишнее в папках лаб и site/.
  • Страховка: перед каждой загрузкой, которая что-то меняет или удаляет, прежние версии этих файлов копируются в old_files/last-sync/ (с теми же путями); предыдущая копия там стирается — хранится ровно один шаг назад. Вернуть файл: скопировать его из old_files/last-sync/ на прежнее место (в консоли Yandex).
  • Сухой прогон без ключей: python3 tools/sync-bucket.py --dry-run — покажет разницу.
  • Сайт читает бакет только по публичным ссылкам; ключи нужны лишь для записи.

Автозапуск после пуша

Файл .github/workflows/sync-bucket.yml: на каждый пуш в main родительского репозитория GitHub забирает его вместе с подмодулями и запускает tools/sync-bucket.py с секретами YC_ACCESS_KEY_ID и YC_SECRET_ACCESS_KEY. Результат виден во вкладке Actions.

Порядок пуша важен: сначала подмодули, потом родитель. Иначе родитель ссылается на коммит, которого нет на GitHub, и запуск падает на checkout (not our ref). Скрипт tools/save-push.sh "сообщение" делает всё по порядку и при ошибке подмодуля родителя не пушит. Подмодуль может стоять в detached HEAD — скрипт пушит HEAD:main.

Сервер и домен

  • Сервер: Ubuntu 22.04, 45.10.166.23 (IPv6 2a03:afc0:9::15c9). Вход только по SSH-ключу, по паролю сервер не пускает (с 05.10.2026): ssh -i ~/.ssh/id_anitech root@45.10.166.23. Секретный ключ ~/.ssh/id_anitech лежит на вашем Mac и защищён паролем-фразой; публичная половина — в /root/.ssh/authorized_keys на сервере. Настройка запрета пароля — файл /etc/ssh/sshd_config.d/00-keyonly.conf.
  • Домен: anitech.meeymirita.ru, DNS — в Cloudflare (зона meeymirita.ru, куплена у REG.RU, там только делегирование).
  • Caddy (systemctl status caddy), конфиг /etc/caddy/Caddyfile. Два сайта:
    • anitech.meeymirita.ru — раздаёт папку /var/www/anitech-performance (file_server, сжатие zstd/gzip);
    • meeymirita.ru — проксирует на 127.0.0.1:8080 (другой сайт на этом сервере).
  • HTTPS выпускает и продлевает сам Caddy, http→https (308) он делает сам. Редиректов в коде страниц нет.

Как сайт обновляется (деплой)

Файлы в deploy/. На сервере лежит клон репозитория /opt/anitech-src; таймер systemd anitech-deploy.timer раз в минуту запускает deploy/deploy-site.sh: подтягивает main, и если версия изменилась — копирует в /var/www/anitech-performance только нужное сайту (index.html, favicon.svg, images/, mira/, works/ без больших картинок). Ключи не нужны: репозиторий публичный. После пуша сайт обновится через ~1 минуту.

# поставить (один раз, на сервере от root)
curl -fsSL https://raw.githubusercontent.com/meeymirita/anitech-performance/main/deploy/install.sh | bash

# посмотреть, когда сработал таймер и что выложено
systemctl list-timers anitech-deploy.timer
journalctl -u anitech-deploy.service -n 20 --no-pager

# выложить прямо сейчас, не ждать минуту
FORCE=1 /opt/anitech-src/deploy/deploy-site.sh

Перед первой установкой скрипт делает копию старой папки сайта: /var/www/anitech-performance.bak-<дата> (потом её можно удалить).

Кеш: если перед сервером снова включат проксирование Cloudflare, после выката может понадобиться Caching → Purge Everything.

Команды

python3 tools/check-site.py              # проверка целостности сайта (запускать перед коммитом)
python3 tools/build-toc.py               # пересобрать works/js/toc.json после правки методичек
python3 tools/build-progress.py          # пересобрать works/progress.html
python3 tools/build-verification.py      # пересобрать works/verification.html из fixes/common/_verification.md
python3 tools/patch-manuals.py           # кнопка «Все работы», защита от мигания (после перевыгрузки методички)
python3 tools/sync-bucket.py --dry-run   # что изменилось бы в бакете
bash tools/save-push.sh "сообщение"      # коммит и пуш: подмодули → родитель
gh run list --workflow "Sync bucket"     # статус автозагрузки в бакет
gh run rerun <id>                        # перезапустить упавший запуск
